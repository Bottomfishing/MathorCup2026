# 最终结果复现与论文取数（优化任务6）

当前统一入口为 `scripts/reproduce_final.py`，覆盖原始标签审计、R2/R2补充Q1、历史标准化Q2组装与文献层、R3原始量尺Q2、任务4原始画像/完整迁移检查、任务5重复嵌套验证。论文由队员撰写，本项交付代码、核验记录及取数文件。

## 从新克隆开始

需要Python 3.12、原始附件目录、原赛题PDF，以及两份固定版本公开数据。公开数据和模型不随Git提交。

```powershell
git clone https://github.com/Bottomfishing/MathorCup2026.git
cd MathorCup2026
py -3.12 -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-r3-lock.txt
.venv/Scripts/python.exe scripts/reproduce_final.py --source '原始附件目录' --output outputs/my_final_run
```

`requirements-r3-lock.txt`包含核心依赖锁及SHAP栈；不需要先另装一套核心依赖。默认调用既有下载脚本获取并校验固定Zenodo工作簿和原始评分CSV。已有离线副本可显式传入，仍核对固定SHA256：

```powershell
.venv/Scripts/python.exe scripts/reproduce_final.py --source '原始附件目录' --statement '原赛题PDF路径' --reference 'Supplemental Files and Figure source files.xlsx的本地路径' --raw 'Raw sensory data anonymized.csv的本地路径' --output outputs/my_final_run
```

输出目录必须不存在。PDF默认位于附件目录上级。每一步记录命令、耗时、退出状态和日志；失败时停止并将`reproduction.json`写为`failed`，只有`passed`才表示整链通过。整个入口会重新训练和独立复核，耗时明显大于只读取已提交结果。

若仅为运行器或取数排版修正，可在相同命令中加`--resume`继续失败目录：已成功的步骤要求命令及科学实现未变，所有数值对照仍重新检查，恢复原因和提交号写入报告。科学实现改变时应使用新输出目录。

## 重建与按版本复用的范围

R2、R2补充、R3、任务4和任务5模型从头拟合，不加载旧joblib；各自核验脚本继续独立复核其声明范围。任务5核验独立重拟合126个学习器及54次生成器。科学表按`1e-10`绝对/相对容差比较，NPZ比较数组键、形状、数值及身份，不比较ZIP时间戳或模型pickle字节。字符串仅统一CRLF/LF；耗时列不参与数值一致判定。

版本复用部分明确保留：Q2的200次重训选择记录、1999次置换零分布和旧森林比较；历史化学/文献配对；Q2旧额外目标的阈值假设证据；任务4的8293个历史合格路径点和任务5的原11条固定路径。Q2核验重新拟合固定Ridge并重数选择记录、P值/BY等；没有重新跑所有历史实验。原始字段/标签定义先从源文件重算对照，随后作为冻结定义使用。

R2补充历史`fit_log.csv`含一次已标明被替代的全样本森林种子，25行；新流程直接拟合正确冻结种子，24行。该历史日志不做逐行相等比较，科学预测表及独立全森林核验仍须通过。

`scripts/reproduce_current.py`的旧19步、旧11/21步脚本及报告保留各自历史范围，不能替代本入口。旧11款迁移结论不适用于当前完整约束。
