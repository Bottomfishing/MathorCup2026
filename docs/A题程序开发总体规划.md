# A 题程序开发总体规划

版本：v1.0；日期：2026-10-23；提交日期：2026-10-30（具体时刻待核实）。
本文件是开发与协作计划，不代表已完成建模或已有实验结果。

## 1. 目标、职责与完成标准

以附件为依据完成三问的程序支持、实验验证、结果表与图、复现说明及论文材料交接。以可追溯、可验证为质量标准，不承诺绝对零错误或获奖。

参赛队员负责独立完成核心建模、算法设计、求解与分析；AI 辅助数据核验、程序实现、调试、文献核查、可视化和文档整理，记录实际贡献。此安排依据随题提供的 AI 工具使用规定。不得把 AI 实际承担的核心工作隐去或仅靠签字替代独立完成。

建议分工：
- 程序负责人：数据语义核对、实验方案理解与实施、运行复核、版本管理、向论文同学解释结果和边界。
- 论文同学一：问题一、二的方法推导、化学依据、参考文献核实，与程序负责人共同确定模型与变量解释。
- 论文同学二：问题三的方法与约束、结果解释、摘要与全文整合、格式及提交检查。
- 三人共同：确认研究假设、评价方法和最终结论；每人能解释自己负责部分。

## 3. 总体顺序与阶段验收

### P0 数据审计与题意落实（10月23日优先）

工作：
1. 生成原始文件清单、SHA-256、编码和表结构清单；保留原文件。
2. 建立样本对照表、化合物别名表、感官指标对应表；列出哪些字段真正回答 Aroma/Flavour，哪些作为补充。
3. 检查缺失、重复、恒定列、非法数值、异常值、矩阵对称性及行列名称对应。
4. 对照校准数据、单位与原始研究，逐列核实 log10/ln/未变换/其他情况；不对所有列盲目取指数，也不把负值一概视为异常。
5. 核实评分卡是不是模板、4.csv 的标准化方式、能否获得原始 0～6 分的恢复参数。
6. 区分实测化合物、理化参数、综合指标、标识字段、目标与辅助资料，形成允许进入模型的字段名单。

产物：data_inventory.csv、sample_mapping.csv、feature_dictionary.csv、sensory_mapping.csv、data_quality_report.md、open_issues.md。

验收：每条连接可追溯；无静默丢失样本；目标维度明确；关键单位有证据；评分尺度方案明确。

评分尺度分支：
- 找到可信原始评分或标准化参数：可验证恢复尺度，保留来源与重建误差。
- 暂未找到：标准化空间的建模可继续，但不得宣称已恢复真实 0～6 分。
- 最终确实不可识别：记录不可识别性，由队员确定并论证校准假设；输出只能标为估计等级，做敏感性分析，不能冒充原始评分。必要时向组委会核实题意。

### P1 验证框架与最小可运行流程（10月24日）

工作：建立数据加载、预处理、划分、基线、指标、结果保存的完整流程。

默认采用固定外层交叉验证，内部进行小规模调参；折数结合稀有风格样本量确定。不能机械使用严格 5 折风格分层，因为部分风格不足 5 个样本。记录各折风格分布，必要时采用兼顾分布的划分及额外风格留出诊断。

同一啤酒的重复记录必须同组；填补、缩放、降维、特征筛选、生成模型拟合都只在相应训练集完成。保存外折预测 OOF，不把训练拟合预测作为泛化结果。若确认现有目标本身采用全样本标准化，明确既有处理限制；恢复原始尺度后再执行折内处理更理想。

产物：split_manifest.csv、baseline_metrics.csv、oof_predictions.csv、运行日志与配置快照。

验收：一条命令可生成基线；标识符不进入特征；验证集不进入任何拟合步骤；随机种子、版本、数据哈希均记录。

### P2 问题一：缺失条件下的感官评分（10月24～25日）

路线：
- 基线：训练集均值/中位数预测，简单填补 + Ridge 或 PLS。
- 候选：Extra Trees、Gradient Boosting 等适合表格数据的模型；按验证表现决定是否增加其他方法，避免无目标堆模型。
- 多输出与逐目标预测比较，必要时利用感官维度间结构，但所有结构学习在训练折内完成。
- 保留原始缺失掩码，在本来已观测的测试特征上额外模拟 5%、10%、20% 缺失，评价鲁棒性；额外模拟缺失不能冒充真实缺失机制。
- 同时保存标准化空间连续预测、经论证校准后的 0～6 连续值与整数等级；区分 OOF 预测、全量拟合后的估计与真实标签。

指标：逐维度 MAE、RMSE、可用时 R²、宏平均及各风格误差；只有具备可信原始等级时才报告等级 MAE、相邻等级命中率等。恒定目标的 R² 应标注不适用。

产物：q1_scores.csv、q1_oof_metrics.csv、missingness_robustness.csv、误差图、缺失鲁棒性图。

验收：评分范围和维度正确；校准有依据；差于基线的目标如实报告；所有正式性能来自样本外预测。

### P3 问题二：网络与 Top-3 因素（10月25～26日）

路线：
- 按题意用 2.csv 构建带正负相关信息的化合物网络，记录阈值与边数，比较阈值变化的影响。
- 将全样本给定网络标为描述性分析；若网络用于筛选预测特征，需在训练折重估网络，不能让全样本信息影响独立验证。
- 结合预测模型、置换重要性/可解释系数及必要时 SHAP，评估各感官维度的重要化合物。
- 对相关化合物记录共线性和替代效应，防止把网络中心性误当成某个感官目标的预测重要性。
- 开发时先少量重采样确认流程，正式分析默认 200 次 bootstrap；根据入选频率的 Monte Carlo 稳定性决定是否增加。预处理和模型应在重采样内重新拟合，不能只重排固定重要性。
- 计算 Top-3 入选频率、不同方法集合的 Jaccard；弱证据不能强行包装成稳定发现。
- 每个维度列出 3 个候选化合物及证据强弱，化学作用与阈值由可靠来源核验。关联及模型重要性不等于因果。

产物：q2_top3.csv、q2_stability.csv、compound_edges.csv、chemical_evidence.csv、网络图与稳定性图。

验收：化合物别名可追溯；理化/综合指标与化合物区分；重采样参数可复现；每项解释有来源或标明待证。

### P4 问题三：风格生成与迁移（10月26～27日）

路线：
- 先建立风格内重采样/简单扰动基线，再比较风格条件的低维概率模型或收缩协方差模型；用跨风格共享信息缓解每类仅数个至数十个样本的问题。
- 仅在数据与验证支持时引入 CVAE 等复杂模型。普通 CPU 能运行基础路线，GPU 不作为启动条件。
- 综合指标尽可能从基础量重算；检查单位、正值约束及相关关系，不独立生成相互矛盾的总量和分量。
- 对 Tripel、Kriek、Lambic 等风格生成化合物谱，通过问题一模型得到感官画像，并标明这是模型估计，不是实际品评。
- 风格迁移采用目标风格接近程度与改动幅度之间的约束优化。检验 Pils/Lager→Tripel 等示例，保留不可行求解结果，不静默放松约束。
- 建立 DMS、Diacetyl、4VG、trans-2-nonenal、Stale hops 对应字段、单位、阈值及来源。Stale hops 等可能是复合感官标签，不能强行当成单一化合物浓度；无直接测量时说明代理与适用限制。
- 对可直接比较的指标，默认使用超阈值严重度 e=max(c/t-1,0)，要求 e_after≤e_before+数值容差；其他单位或代理指标另行定义。所有指标必须同一量纲，题目指定的缺陷规则优先执行，风格差异用于解释。

验证：留出真实样本上的分布一致性、相关结构、多样性、最近邻复制检查、风格识别诊断、约束违反率、改动幅度。风格分类器分数只作诊断，不作为唯一成功标准；小样本结论注明不确定性。感官画像通过同一预测器得到，并非独立化学有效性的证据。

产物：q3_generated_profiles.csv、q3_generated_sensory.csv、q3_transfer_pairs.csv、q3_constraint_checks.csv、生成验证表、迁移前后图。

验收：每条输出有来源风格/目标风格、seed、方法、约束检查；可行样本约束满足；不可行样本明确标记；不宣称未经酿造验证的现实可实现性。

### P5 正式实验、交叉核验与论文交付（10月28～29日）

- 10月28日完成必要模型比较、消融、敏感性、稳定性实验，冻结主要方法和配置；只保留回答具体研究问题的实验。
- 10月29日完成最终运行和结果冻结，确保论文表格与程序结果一致；之后若修正错误，生成新版本并通知论文同学。
- 在干净虚拟环境重新安装锁定依赖并运行完整流程，核验输出哈希或合理数值容差。
- 对每类关键结果抽样手算/独立公式复核，不以“没有报错”代替正确性验证。
- 形成结论—表格—实验编号对应表；结果有变化时自动重生成图表，禁止人工拼接不同轮实验的最优数字。

仅做打包、文件可读性、结果与论文一致性、隐私信息及复现说明检查，保留提交缓冲。须核实官方具体截止时刻；不能默认当天 23:59。

## 4. 程序架构与数据约定

建议 Python + pandas/numpy/scipy/scikit-learn/networkx/matplotlib；Excel 读取用 openpyxl。先检测本机环境，再按必要依赖安装并固定版本。解释工具或其他模型库按实验需要引入。

目录（本阶段仅创建规划文件，其余为拟建）：

```text
configs/                 数据路径、随机种子、实验与约束配置
src/                     io、audit、preprocess、validation、q1、q2、q3、reporting
tests/                   数据连接、变换、评分、泄漏、约束和端到端关键测试
data/processed/          处理后数据及数据字典；原始附件保持不动
outputs/<run_id>/        配置、数据哈希、日志、模型、表格、图
deliverables/paper/      已冻结的论文图表、方法说明和结论索引
docs/                    计划、审计、决策记录、交接说明、AI 使用记录
README.md                环境、命令、输出解释、复现步骤
```

计划命令接口：audit、baseline、q1、q2、q3、report、reproduce；实际脚本接口在搭建时确定。

所有预测/生成表至少保留样本或生成 ID、风格、目标名称、值、尺度、方法、fold（适用时）、run_id。所有指标说明是训练、OOF、留出还是生成诊断。阈值配置必须同时保存单位、来源和适用范围。

## 5. 错误控制与停止条件

必须直接阻止运行的错误：重复主键导致多对多连接；模型输入含标签或 ID；关键单位不明确却计算阈值；评分卡模板零值被当作标签；输出无穷/非法值；迁移失败却标成功；划分的同一样本同时出现在训练与验证。

必须记录而不能隐藏的情况：模型未优于基线、部分 Top-3 不稳定、无法精确恢复原始评分、稀有风格无法可靠评估、生成分布不匹配、约束不可行。

测试重点：连接与行数守恒、log/原尺度转换往返、标准化与反变换、缺失掩码、训练折隔离、评分范围、阈值单位与边界、指标复算、可行/不可行迁移案例。

## 6. 给论文同学的交接规范

每个问题交付：
1. 输入输出、模型假设、公式及参数含义；
2. 实际采用的方法与选择依据，方法局限；
3. 可直接引用的 CSV 结果、清晰图表（PNG + PDF/SVG）及图注草稿；
4. 每个主要结论对应的实验编号和证据表；
5. 指标的计算方式、数据划分与不确定性说明；
6. 文献来源与 AI 实际辅助记录。

论文同学可以立即开展题意分析、文献核实、符号表和结构写作；正式结果与摘要数字在结果冻结后填写。开发中间结果必须标为 preliminary，不与 final 混用。

## 7. 优先级与范围控制

P0 必须：评分语义与量纲核验、无泄漏验证、三问完整基线、稳定性、生成与迁移约束、可复现交付。
P1 应做：缺失鲁棒性、模型对比、消融、阈值敏感性、解释一致性。
P2 可选：复杂深度生成、大规模调参、交互展示。只有 P0/P1 完成且证据表明有益时才做。

优先推动下一步：数据审计及评分尺度可识别性核验。暂不开展大规模调参或正式生成模型训练。
